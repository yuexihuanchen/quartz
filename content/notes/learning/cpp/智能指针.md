## 引用和指针
指针是一种独立的对象，用来保存另一个对象的地址；引用则是一种语言层面的别名关系，用来表示对已有对象的直接访问。
```
std::string s = "Hello";
std::string& r = s;
std::string* p = &s;
```
假设 `s` 的地址是 `0x1000`。

## 指针存在的问题
可以把 **C++ 裸指针管理内存** 想象成：
> **堆上的对象 = 一套出租屋**  
> **指针 = 房子的钥匙**  
> **delete = 把房子拆了**  
> **nullptr = 手里的钥匙作废了**

### double free
```
int* p = new int(10);

delete p;
delete p;   // ❌ double free
```
`new int(10)` 在堆上申请了一块内存，第一次delete p 告诉操作系统 指针指向的这块内存不用了，但要注意 **delete p 释放的是p 指向的对象，并不会自动把p变为nullptr** 所以p 里面还保存着原来的指向地址，这种指针叫==悬空指针==

### 悬空指针（Dangling Pointer）
```
std::string* p;

{
    std::string s = "Hello";
    p = &s;
}

// s 的生命周期已经结束

std::cout << *p; // 未定义行为
```
这里 `p` 仍然是一个存在的指针对象，但是它保存的地址不再对应一个存活的 `std::string` 对象。

引用也可能悬空：
```
std::string& getString()
{
    std::string s = "Hello";
    return s;
}
```
函数返回后 `s` 已经销毁，返回的引用不再有效。

**一个对象的访问关系可以仍然存在，但被访问对象的生命周期可能已经结束。**
有一个特殊情况值得记住：
```
const std::string& r = std::string("Hello");
```
这里临时 `std::string` 对象的生命周期会延长到局部引用 `r` 的生命周期结束。
但这属于 C++ 规定的特定临时对象生命周期延长规则，不代表引用普遍具有延长对象生命周期的能力。

如果 这之后又来了一次 delete p，相当于房子已经拆了，又要求再去拆一遍，这就是 ==double free==🟡 即重复释放同一块内存，这属于==Undefined Behavior（未定义行为）==。
所以以前使用裸指针，经常写：
```
delete p;
p = nullptr;
```

但是这还有一个情况，如：
```
int* p1 = new int(10);
int* p2 = p1;

delete p1;
p1 = nullptr;

cout << *p2;   // ❌
```
内存关系原本是：
```
p1 ─────┐
        ▼
      ┌────┐
      │ 10 │
      └────┘
        ▲
p2 ─────┘
```
执行：
```
delete p1;
p1 = nullptr;
```
以后：
```
p1 ───► nullptr

p2 ───► 0x1000
         ╳ 内存已经被释放
```
`p2` 并不会神奇地一起变成 `nullptr`。

所以真正的问题并不是： “有没有把指针设为 nullptr？”而是 **到底谁拥有这块内存？谁负责释放它？** 这也是理解智能指针最核心的一句话：**智能指针解决的本质问题是：所有权（ownership）和生命周期（lifetime）。**

## RAII
Resource Acquisition Is Initialization > **资源获取即初始化**
核心思想非常简单：**不要让程序员手动记住什么时候释放资源。**
让一个对象来帮你管理。
对象生命周期结束时：析构函数 自动释放资源。智能指针就是 RAII 最典型的应用之一。

## 1、unique_ptr
```
auto p = std::make_unique<int>(100);
```
含义： 这块内存只有 **一个 owner**。

也就是：
```
unique_ptr p
      │
      │ 唯一拥有
      ▼
┌────────────┐
│    100     │
└────────────┘
```

不允许：
```
auto p1 = std::make_unique<int>(100);

auto p2 = p1;    // ❌
```

我们不能拷贝或赋值unique_ptr，但可以通过调用release或reset将指针的所有权从一个（非const）unique_ptr转移给另一个unique。
unique_ptr有一个成员方法就是release，release可以返回unique_ptr的内置指针，并将unique_ptr置为空。
不能拷贝unique_ptr的规则有一个例外：我们可以拷贝或赋值一个将要被销毁的unique_ptr。 最常见的例子是从函数返回一个unique_ptr：
```
unique_ptr<int> clone_unique(int a)
{
    return unique_ptr<int>(new int(a));
}

void use_uniqueptr()
{
    int a = 1024;
    unique_ptr<int> mp = clone_unique(a);
    cout << *mp << endl;
}
```

## 2、shared_ptr
```
auto p1 = std::make_shared<int>(100);

auto p2 = p1;
auto p3 = p1;
```
这时候：
```
p1 ──────┐
         │
p2 ──────┼────► 100
         │
p3 ──────┘

引用计数 = 3
```
即可以同时有多个 shared_ptr指针 指向同一个内存对象。

## 3、weak_ptr
我可以观察这个对象，但我不拥有这个对象。
主要和shared_ptr 组合使用，解决shared_ptr 可能存在的循环引用问题
```
class B;

class A
{
public:
    std::shared_ptr<B> b;
};

class B
{
public:
    std::weak_ptr<A> a;
};
```

关系变成：

```
A ──shared_ptr──► B
▲                 │
│                 │
└── weak_ptr ─────┘
```

A：

> “B 是我的，我对 B 的生命周期负责。”

B：
> “我认识 A，但我不负责让 A 活着。”

所以 weak_ptr 不会增加引用计数。
