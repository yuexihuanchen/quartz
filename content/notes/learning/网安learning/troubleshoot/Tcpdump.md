Tcpdump is a command-line packet analyzer that captures and displays network traffic going through a system.

命令行网络数据包分析工具（Packet Analyzer）
**tcpdump抓的是：==数据包 Packet==**

![[ex_tcpdump.png]]


**tcpdump 就像网络世界的一台慢动作摄像机 + X 光机——它不主动说话，只是静静地站在网卡旁边，把每一个经过的数据包拆开、拍照、存档。当网络出了问题，当怀疑有数据在偷偷外泄，当需要证明"问题不在我这儿"时，tcpdump 捕获的 pcap 文件就是最有力的证据。在命令行的黑白世界里，它是网络工程师和安全分析师最信赖的"第三只眼"。**

### tcpdump 主要用于：
1. 网络故障排查：检查网络是否连通，定位丢包、连接异常等问题。
    
2. 网络协议分析：分析 TCP、UDP、ICMP、DNS、DHCP、HTTP 等协议通信。
    
3. 网络安全分析：识别异常连接、可疑流量及端口访问行为。
    
4. 数据包过滤：按照 IP 地址、端口、协议、TCP 标志位等条件抓取数据。
    
5. 流量统计与分析：统计网络通信情况，辅助识别主要流量来源。
    
6. 抓包文件保存：将网络数据保存为 PCAP 文件，供 Wireshark 等工具进一步分析。

### 基本命令格式
tcpdump 的基本语法为：
```
sudo tcpdump [选项] [过滤表达式]
```
常用参数如下：

|参数|功能说明|
|---|---|
|`-i`|指定抓包网络接口|
|`-n`|不将地址解析为名称|
|`-nn`|不解析主机名与端口服务名|
|`-c`|指定抓取数据包数量|
|`-A`|以 ASCII 形式显示数据包内容|
|`-X`|同时以十六进制和 ASCII 显示|
|`-s`|设置数据包捕获长度，`-s 0` 用于完整捕获|
|`-v`|输出更详细的信息|
|`-vv`|输出更高详细程度的信息|
|`-l`|使用行缓冲模式输出|
|`-U`|逐包刷新输出，适合实时 PCAP 管道|
|`-w`|将数据包保存到文件|
|`-r`|读取抓包文件|
|`-t`|不显示时间戳|

## 实验环境准备

部分命令需要特定的源 IP、目标端口和 HTTP 流量。如果直接在一台没有对应通信的 Linux 主机上运行，可能一直没有输出。
建议准备两个终端窗口：
- 终端 A： 执行 tcpdump 抓包命令。
    
- 终端 B： 执行 ping、curl、dig 等操作，主动产生测试流量。
    

涉及 HTTP 的实验可以在本机部署一个简单的测试服务器。

在终端 B 中执行：
```
mkdir -p /tmp/tcpdump-lab
cd /tmp/tcpdump-lab
echo "tcpdump test" > index.html
sudo python3 -m http.server 80 --bind 127.0.0.1
```

保持该终端运行，另外打开一个终端，执行：
```
curl -v http://127.0.0.1/
```

如果返回页面内容 `tcpdump test`，说明本地 HTTP 测试服务器已经正常运行。

这个服务器只监听 `127.0.0.1`，用于本机实验；实验结束后用 `Ctrl + C` 停止服务。

后续 HTTP 实验统一使用该服务器，抓包接口选择 `lo`，这样更容易获取清晰、可重复的截图。

注意： 以下命令中的 `10.5.2.3`、`10.0.2.4` 是你指定的实验地址。执行相关实验时，必须确保相应源 IP 确实存在并产生流量；如果没有，应改为实际实验主机地址。所有抓包操作均应在自有或获得授权的网络环境中进行。

#### 实验 01：组合过滤——源 IP + 目标端口
实验目的
掌握使用 `and` 逻辑运算符，同时限定数据包的源 IP 地址和目标端口，实现精确抓包。

操作命令
```
sudo tcpdump -i lo -nn 'src 10.5.2.3 and dst port 3389'
```
![[Pasted image 20261012204428.png]]

实验结果表明，tcpdump 成功捕获了源 IP 地址为 192.168.241.129、目标端口为 3389 的 TCP 数据包。抓包结果显示，源主机向目标主机 192.168.241.2 的 3389 端口发送了 SYN 连接请求，符合设定的源 IP 与目标端口组合过滤条件，验证了 tcpdump 使用 and 运算符进行多条件过滤的有效性。

### 实验 02：多条件带括号组合过滤
实验目的
掌握 `and`、`or` 逻辑运算符和括号的使用，实现多条件组合过滤。

操作命令
```
sudo tcpdump -i lo -nn 'src 10.0.2.4 and (dst port 3389 or dst port 22)'
```
步骤
```
sudo tcpdump -i ens33 -nn 'src 192.168.241.129 and (dst port 3389 or dst port 22)'
```
另外打开一个终端，依次执行：
```
nc -zv -w 2 192.168.241.2 3389
nc -zv -w 2 192.168.241.2 22
```
结果

实验过程中，使用 tcpdump 的组合过滤表达式，对源 IP 地址及目标端口进行联合筛选。抓包结果显示，成功捕获了两条由 192.168.241.129 发往 192.168.241.2 的 TCP 数据包，目标端口分别为 3389 和 22，两条报文均携带 SYN 标志位，表示主机正在发起 TCP 连接请求。实验结果与预设过滤条件一致，说明通过 and、or 逻辑运算符及括号组合，可以实现多条件网络数据包的精确过滤，提高抓包分析的针对性。

### 实验 03：行缓冲输出，配合管道 grep 过滤输出
实验目的
掌握 tcpdump 的 `-l` 行缓冲参数及 Linux 管道符 `|` 的使用方法，通过 `grep` 对抓包内容进行筛选，提取 HTTP 响应报文中的 `Server:` 字段，实现网络数据的实时过滤与分析。
操作命令
```
sudo tcpdump -l -A -s 0 'port 80' | grep --line-buffered -i 'Server:'
```
其中，`-l` 表示行缓冲输出，`-A` 表示以 ASCII 格式显示数据内容，`-s 0` 表示完整捕获数据包，`grep` 用于提取包含 `Server:` 的内容。

步骤
1. 启动 HTTP 测试服务器
打开终端 1，执行：
```
sudo python3 -m http.server 80 --bind 127.0.0.1
```

正常情况下会显示：
```
Serving HTTP on 127.0.0.1 port 80 ...
```
保持该终端运行。

2. 启动 tcpdump 抓包

打开终端 2，执行：

```
sudo tcpdump -i lo -nn -l -A -s 0 'tcp port 80' | grep --line-buffered -i 'Server:'
```

这里使用 `lo` 网卡，因为我们要抓取本机 `127.0.0.1` 的 HTTP 通信，而不是 `ens33` 网卡上的流量。

3. 产生 HTTP 测试流量

打开终端 3，执行：

```
curl -I http://127.0.0.1/
```

这条命令会向本机 HTTP 服务器发送 HEAD 请求，服务器返回包含 `Server:` 字段的 HTTP 响应头。
